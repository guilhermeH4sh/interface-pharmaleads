# M13 — interface comercial com dados reais

Antecipado por autorização humana para apresentação e uso definitivo. Paleta consultada no CSS
público de https://centrusai.com: primary hsl(252 100% 65%), soft-lilac hsl(252 100% 97%).
Referência de layout: quadro enviado pelo usuário; componentes leves e superfícies claras.

Login Supabase por e-mail/senha, sessão só em memória (recarregar exige novo login), quadro por
status real, lista, filtro UF no servidor, busca textual no recorte carregado, paginação por ID,
ficha cadastral e erros 401/403. Nenhum lead/contador demonstrativo faz parte do produto.

Configuração do frontend: VITE_API_URL (padrão https://pharmaleads.onrender.com) e
VITE_SUPABASE_PUBLISHABLE_KEY. Sem a chave de build, há campo de configuração na entrada.
Nunca configurar JWT secreto ou service_role no frontend. Backend precisa permitir a origem real
em PHARMALEADS_ALLOWED_ORIGINS. Usuário deve possuir escopo CRM (admin/gestor/privacidade ou
comercial com leads atribuídos); operador não tem esse acesso. Não foram ampliadas permissões.

GET /v1/leads agora projeta também status, CNAE, bairro e endereço existentes em pharmaleads.
As contagens são do recorte carregado, não do banco inteiro. Campos nulos indicam não informado.
Sem simular edição, exportação ou coleta. Contatos aguardam endpoint com elegibilidade por fonte.

Pendentes para aceite M13: prova autenticada real, edição comercial M11, contatos/evidências,
atividades/histórico, exportação M12, cliente gerado OpenAPI e demais fluxos previstos no contrato.

Verificação local: TypeScript, ESLint e build Vite aprovados; dois testes de login/ausência de
dados passaram. Chromium inspecionou login 1440×900 e 390×844 sem overflow horizontal.
Não houve login real nem leitura autenticada do Supabase nesta entrega; exige conta autorizada.
