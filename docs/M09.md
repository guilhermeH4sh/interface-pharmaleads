# M09 — navegador seletivo para páginas dinâmicas

Objetivo: usar um navegador isolado apenas quando a coleta HTTP autorizada do M08 não
conseguir renderizar uma página efetivamente dinâmica. Não haverá browser como fallback
automático, nem download indiscriminado de binários.

Estado em 27/10/2026: **aceito em 27/10/2026**. O contrato seletivo foi implementado com Playwright
assíncrono: um contexto/página não persistente, Service Workers bloqueados, limite de
requisições/HTML/tempo, bloqueio de outro host, downgrade HTTPS e mudança de DNS, e
fechamento em `finally` de página, contexto, browser e runtime. O M08 continua sendo a via
padrão; não há fallback automático.

Foi executada a prova local `ops/verify_m09_browser.py`: Chromium renderizou `mailto:`
inserido por JavaScript e fechou browser/contexto/página (`{"rendered_mailto": true,
"leaks": false}`). Nenhum site externo nem dado do Supabase participou da prova.

O enfileiramento e worker dedicados foram incluídos: `m09_cli` exige a razão explícita
`dynamic_after_http`, uma coleta HTTP M08 concluída e site M07 ainda confirmado. O worker
reivindica somente `crawl_browser`, preservando o worker Scrapy para `crawl_http`; o checkpoint
registra comparação de contagens HTTP × browser e não promove contatos comerciais.

Aceite executado em `ops/verify_m09_browser.py`: a página controlada tinha zero contato no
equivalente HTTP e um `mailto:` inserido por JavaScript; o browser informou um contato adicional,
fechou popup, bloqueou a subrequisição sintética externa, reconheceu timeout e terminou sem leak.
Ruff e mypy dos arquivos M09 passaram. Não foi feito fluxo remoto porque nenhum lead do piloto
foi classificado como efetivamente dinâmico; isso é decisão operacional futura, não pendência do
módulo.

Em revisão do cenário popup, foi corrigido o fechamento assíncrono: o callback agora agenda
`popup.close()` no loop, em vez de abandonar uma coroutine. O teste de egress que bloqueia host
externo e mudança de DNS passou; a prova integrada confirmou popup e timeout.

Na prova controlada, uma única instalação por máquina será feita no backend:

```powershell
.\.venv\Scripts\python.exe -m playwright install chromium
```

No Linux, use `python -m playwright install chromium`. Não execute isso como parte do crawl
nem em cada job. Na máquina atual, o binário ficou fora do Git, em diretório local do Playwright.

O resultado continuará como observação, sem promoção comercial direta e sem criar tabela
adicional. O M08 permanece a via padrão para sites estáticos.
