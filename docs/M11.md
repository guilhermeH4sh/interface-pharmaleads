# M11 — API CRM e histórico

Objetivo: disponibilizar consulta e edição comercial com autorização, versionamento e histórico.

Implementada consulta cadastral GET /v1/leads e GET /v1/leads/{lead_id}, usando o JWT do
usuário na Data API e chave publicável configurada. Comercial recebe filtro obrigatório por
responsável; admin/gestor/privacidade reutilizam leads:read; operador/revisor não recebem acesso
CRM. Matriz provisória M03 preservada, decisão D-07 ainda aberta.

Paginação estável por id ascendente com after_id e até 100 itens. Filtros UF e CNPJ combináveis,
validados e codificados via urlencode. Sem SQL construído. Respostas projetam apenas campos
cadastrais; contato/evidência aguardam elegibilidade por fonte. Tempos reais de consulta são
registrados sem credenciais nem dados pessoais. Nenhuma mudança no Supabase realizada.

Verificação: 17 testes M11/auth passaram fora do sandbox (TestClient bloqueou dentro do
isolamento), Ruff e mypy aprovados. Cobrem autenticação, escopo por responsável em lista/ficha,
ausência 404, bloqueio de operador, filtros, cursor e parâmetros inválidos.

Estado: em andamento. Faltam PATCH CAS, atividades, contato informado diretamente (D-17),
histórico, filtro de elegibilidade dos contatos, testes de concorrência/preservação e prova remota.
Histórico JSONB com append pela API não garante imutabilidade contra acesso direto de quem tem
UPDATE na coluna; a restrição de uma tabela/nenhum objeto auxiliar impede declarar esse aceite
sem solução ou decisão explícita. D-07 permanece aberta, sem ampliar permissões remotas.
